# Terrain rock navigation

ZombieAI roaming, chasing and stalking, plus PowerStationWatcher roaming, now use a shared scene-local Unity navigation surface and independent per-enemy routes. Multiplayer clients still follow replicated transforms; only existing server/offline movement calls request paths. Surveyor radial apparition behavior is unchanged.

TerrainRockNavigation collects ground/static collision geometry and explicitly adds unwalkable volumes for each painted rock instance using the prefab mesh bounds, child transforms, root scale, terrain position, tree rotation, width and height. Sources come from TerrainData.treeInstances, not visible renderers, camera distance, tree billboards, or distance-activated colliders. Tiny rocks under 20 cm are step-over stones. Navigation uses 60 cm radius, 2 m height, 25 cm climb, and 42 degree slope.

Navigation builds asynchronously once per loaded gameplay scene. Monsters pause horizontal movement until the surface is ready, avoiding blind movement during generation. The current 4 km terrain took about 16.2 seconds for a synchronous isolated editor test; runtime background timing can differ. Scene destruction cancels pending work and removes the registered navigation data. Editing terrain or rock placement during an already running game requires reloading the level.

Painted rock physics is supplied separately by `TerrainRockCollisions`. On scene load, every peer builds static mesh colliders from the actual painted rock meshes, preserving terrain positions, rotations, instance width/height and prefab root scale. On the planet terrains, which contain only rock tree prototypes, these meshes also render the rocks and native terrain tree rendering is disabled. This makes each visible mesh match its collider and avoids unsupported Standard-material tree/billboard transforms. Grass details remain enabled. The objects have no NetworkObjects and disappear with their scene. Navigation excludes these generated rock copies from source collection because the painted instances already have explicit obstacle volumes. `TerrainRockCollisionChecks.Run` verifies real player/monster CharacterController blocking with terrain rendering and native terrain collision disabled, plus valid collider coverage in all four saved night scenes.

Each enemy retains its authored wandering direction whenever its next two metres are unobstructed, including when the bunker route has multiple corners. Blocked or stalled movement falls back to path corners. Obstacle routes recalculate at most every 0.65 seconds, when the target moves over 2 m, or when stalled. Partial paths stop at the reachable endpoint rather than pushing through an obstruction. Existing per-night tuning, AI target selection, memory, attack timing, defense and transform replication remain in place.
