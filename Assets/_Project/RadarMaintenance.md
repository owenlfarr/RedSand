# Radar wear and shared repair station

Each new night starts the radar at full durability: Night 1 / Night1_MultiplayerTest = 18 scans, Night 2 = 16, Night 3 = 14, Night 4 = 12, Night 5 = 10, Night 6 = 8, then two fewer per night, with a minimum of one scan in very late nights. The existing radar status and interaction prompt show uses remaining. Only accepted, successful scans consume a use; cooldown, dead/out-of-range players, power/flare lockouts and missing-objective failures do not. The final allowed scan still returns its result, then zero uses locks the radar until repaired. Power restoration and solar repair do not refill wear.

The existing SolarFlareSystem.fixPointTransform doubles as the radar repair point. Hold E for the station's existing repairTime (normally five seconds). Repairs can refill partially worn or fully broken radar. Nights 1?4 charge 10 team metal; Night 5 onward charges 15. The material comes from the drill's shared stockpile. The complete price is charged only on completion; canceled, unaffordable, out-of-range, dead/disconnected or overlapping repair requests do not charge. Repairing restores the full scan capacity and preserves the existing cooldown. Solar flare repair keeps priority, its original cost/behavior and its existing presentation.

The host owns scan durability, repair owner/progress, validity checks and the atomic metal debit. Clients send held-E heartbeats; missing heartbeats, releasing E, leaving the station or dying cancel progress. The server writes shared material state through DrillSessionStockpile so all drill displays and late joiners receive the debit. Offline play uses the current offline drill inventory. Broken radar adds RADAR REPAIR compass guidance when neither a power outage nor solar flare needs priority.

No station or scene assets are duplicated: RadarSystem installs RadarRepairStation automatically, and policy reads each scene's night number. For later authored night scenes, keep the existing radar, solar repair-point reference and drill economy.

Tools > Night Testing > Build Radar Wear Network Checks builds an isolated host/client/late-join executable under Logs/RadarWearBuild. Run with -radarTest host, -radarTest client, then -radarTest late after Logs/Radar-latejoin.ready appears. Results are written under Logs/Radar-ROLE-PASS.txt or FAIL.txt.

Validation: the isolated Windows build succeeded with zero build errors. A real host, joined client and late joiner passed 23 assertions covering scan budgets, cost tiers, successful-scan-only wear, worn lockout, a client repair, atomic payment, insufficient funds, concurrent repairers, release/heartbeat cancellation and replicated late-join state. Test station duration was shortened in the isolated scene; production repairTime values were preserved.
